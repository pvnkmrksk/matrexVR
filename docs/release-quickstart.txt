1. EXTRACT AND OPEN

Extract the whole operating-system ZIP and keep its files together. Launch the
.exe (Windows), .app (macOS) or .x86_64 (Linux). Unity Editor and Python are not
required for the player. macOS is ad hoc signed but not notarized; use Finder Open and the corresponding
Privacy & Security option if prompted. Linux requires a graphical desktop and a
compatible graphics driver; restore executable permission if extraction loses it.
Bundled Linux HejjéTrac requires glibc 2.39 or newer. The Unity player build and
the native tracker have separate operating-system requirements.

A fresh profile opens Home, full screen at the display's native resolution. Choose
Night sky or Forest, then Start demo. No camera, animal or LED hardware is needed.
Flying uses simulated input; Demo options also offers a walking recorded sample.
Use Configure for a real apparatus. Existing sequences keep their startup flags.
Use -configure to open setup if an existing sequence auto-starts. On macOS:
  open "/path/to/MATREX VR.app" --args -configure
Press Escape during an experiment or replay to return to setup.

2. CONFIGURE THE APPARATUS AND ANIMALS

Configure: choose walking/flying, LED panels or desktop preview, rig count,
panel dimensions/order, display, tracker endpoint, species and sphere diameter.
Save with Use this configuration. Use Initialize tracking to inspect input and
calibration before starting an experiment. It creates no experiment pose recording;
a tracker launched with video enabled may already record during preflight.
Daily work then centers on the experiment
sequence and animal details. The public starter is not a hardware calibration.
Modern modes are Rekkefly (flight) and HejjéTrac (walking). Legacy Kinefly/FicTrac
publishers remain available; walking uses cumulative displacement, not flight yaw.

Launch bundled native trackers with Start can start eligible local modern inputs.
Review camera selection and calibration in the tracker before using real animals.
Trackers run independently; quitting Unity does not quit their windows. Start the
dashboard from its UI action to open the separate bundled browser viewer; Python
is not required. Reuse an existing tracker/dashboard instead of starting copies.
For remote telemetry, explicitly configure its bind/subscriber address and network.

The release manifest records exact companion sources, hashes and local corrections.
The reviewed strict-camera correction and newest dashboard are Mac arm64 builds;
Intel Mac, Windows and Linux retain their pinned official companion builds. The
older bundled Rekkefly camera path is blocked because it cannot guarantee camera-only
input. Hardware-free demos work; use an externally verified compatible tracker for
live flight on those platforms. Live walking still needs apparatus calibration and
testing on its acquisition workstation. No live camera fallback is presented as data.

Session: enter experimenter/comments and one Animal ID/Species per configured rig.
VR1, VR2, etc. are hardware routing keys; Animal ID labels the real animal. Species
is saved as per-rig system speciesName and run-metadata SpeciesName. Add rig copies
the prior layout/endpoint with a new ID/port; review it for your actual equipment.
Additional scene rigs are provisioned from authored templates. Independent stimulus
layers are finite; setup reports when a configuration exceeds available capacity.

Sequence config: arrange blocks. Experiment configs: choose/edit complete recipes
for Choice, night sky, Swarm, Kannadi, Optomotor and rugosity. Auto start affects the
next launch. Save setup, then Start experiment. Each run gets its own data folder.
Included scenes (14): ControlScene, Choice, Choice_desync, Choice_Selwyn, Swarm,
Kannadi, Optomotor, TerrainCueLab, Rugosity_RS, ReplayScene,
TerrainChoice_RoughLeft_SmoothRight, TerrainChoice_SmoothLeft_RoughRight,
TerrainChoice_BothSmooth and TerrainChoice_BothRough. The starter Forest uses
Choice_Selwyn with tree objects. Other sourceBuildOnly scene examples require a
custom Unity build.

Terrain choice: load one of these sequence files under Examples/Rugosity/:
  sequence-treatment-matched-terrain.json
  sequence-treatment-visual-terrain_navigation-flat.json
  sequence-treatment-visual-flat_navigation-terrain.json
  sequence-treatment-matched-flat.json
Each runs all four spatial layouts for 30 seconds each. Visual and navigation
surfaces are independent; four shared scenes cover all sixteen combinations.
Both-flat trials intentionally have identical geometry. Edit shared motion, eye
clearance and texture defaults in terrain-treatment.json: centimeters, 1 cm
clearance, texture scale 4, real tracking enabled and scripted autopilot disabled.
The two placeholder trees are equally distant from the start.

For ordered swarm entrainment followed by social interaction, load
Examples/Sequences/swarm-entrainment-social.sequence.json. The matched direct
control is Examples/Sequences/social-coupling-control.sequence.json. Shared
Kannadi/social-coupling.example.json uses numberOfRings: 0 for no extra clones.

Choice block: Edit config -> Available objects & materials lists registered scene
assets. Stimulus -> Objects -> Type/Material offers exact-name dropdowns, alongside
preserved custom JSON values.

3. WRITABLE CONFIGURATION AND RECORDINGS

The current player keeps configuration in Unity's writable per-user profile:
  <persistentDataPath>/Config/   — editable system, sequence, experiment files

Recordings belong to this installed player:
  <player directory>/MATREX VR RunData/
The macOS directory is beside the .app, outside its signed bundle. On Windows and
Linux it is beside the executable. A protected installation uses the stable
fallback <persistentDataPath>/Installations/<installation-id>/RunData/.
Replay recordings shows the exact root above its list. Archived 0.3 players used
the shared <persistentDataPath>/RunData/; Browse can inspect those earlier runs.
Existing recordings are not moved automatically.

Unity normally places that profile under:
  Windows: %USERPROFILE%\AppData\LocalLow\<Company>\<Product>
  macOS: ~/Library/Application Support/<Company>/<Product>
  Linux: $XDG_CONFIG_HOME/unity3d/<Company>/<Product>
         (usually ~/.config/unity3d/<Company>/<Product>)
Company/Product depend on the build's Player Settings; refer to the README/source.
On first use, missing bundled files are copied to Config. Updates NEVER replace an
existing user file. Editor defaults remain Assets/StreamingAssets and Assets/RunData.

Override either directory explicitly, for example:
  "./MATREX VR.x86_64" -configure --config-dir "/path/to/config" --data-dir "/path/to/runs"

Versions 0.1/0.2 used bundled application-relative configuration/data directories.
To migrate, copy their complete configuration tree to a chosen writable directory
and use --config-dir; preserve their run folders and use --data-dir when desired.
Do not overwrite an old run with today's configs.

4. UI AND JSON

Forms and Edit JSON use the same document. Unknown extensions, omitted values,
null/false/zero distinctions and exact untouched numbers survive. An unchanged
save preserves original bytes; an actual edit formats JSON. Showing Inherited
defaults does not insert them. Undo/Redo retains 32 edit transactions. Revert to
saved JSON and Reload disk are undoable. Apply/discard pending raw JSON text before
navigation or saving. External conflicts block overwriting unsaved local changes.
Each file saves atomically with a .bak; the workspace is not one global transaction.

Preferred simulated-population fields:
  agentCount        (old numberOfLocusts still accepted)
  agentSpeed        (then locustSpeed, then locoSpeed as fallbacks)
  agentSpeedStdDev  (old locustSpeedStdDev still accepted)
Canonical non-null values win; zero is explicit. Speed remains scene world units/s.

New AnimalMetadata.json stores Animals/AnimalID/SpeciesName/UsedAnimalIDs. It also
writes legacy FlyMetaData.json and Flies/FlyID/UsedFlyIDs aliases for old analysis.
Read/count one canonical Animals collection, rather than adding the aliases again.
Historical CSV headers and serialized Unity asset identities remain compatible.

5. CONTROLS AND TELEMETRY

R                 Reset rigs to experiment initial pose.
P / O             Toggle tracked position / orientation.
Arrows; A / D     Manual translation; positive / negative yaw, when enabled.
Ctrl + Space      Toggle configured forward autopilot (steering/reverse retained).
Shift+Up/Down     Adjust manual translation speed by 1 per press.
Shift+W/S         Adjust manual turn speed by 1 degree/s per press.
C/Z; W/S; E/Q     Vertical; pitch; roll, when permitted in system config.
Tab               Show/hide runtime dashboard; normal field navigation in setup.
Escape (release)  Return to Control/setup; from Control, quit the player.
Overview          Right-drag orbit, middle-drag pan, wheel zoom inside the image.

Kinefly: +/- yaw gain; Ctrl+Y yaw-rate mode; keys1–9 select matching configured VR
IDs; 0 or the HUD Next animal button cycles every configured ID, including VR10.
Hold [/] to adjust the selected animal’s DC offset. Metadata text entry suppresses experiment hotkeys. Dashboard
Auto Trim controls the current sequence row; new errors can reopen the panel.

Telemetry is a separate outbound PUB, not the tracking SUB stream:
  tcp://127.0.0.1:9880; default20Hz; frames: matrex.telemetry.v2, then JSON
  schemaVersion:2. Use an external ZMQ subscriber; static web pages cannot consume
  raw ZMQ. See docs/heading-reference-telemetry.md and tools/listen_telemetry.py.

6. REPLAY A SAVED RUN

Keep/extract the complete run folder with rig CSVs, population gzip logs, saved
sequence/system/experiment snapshots, config_manifest.json and Skyboxes/.
Choose Replay in setup, or launch:
  "./MATREX VR.x86_64" --replay-session "/path/to/session-folder"
  open "/path/to/MATREX VR.app" --args --replay-session "/path/to/session-folder"

ReplayScene Browse opens a native folder picker on Windows/macOS and in the
Editor. Linux uses zenity/kdialog when installed; paste a folder path otherwise.
Open run folder loads the chosen path. Editor folder drag/drop works; native
standalone OS-drop is not implemented. Use Browse, the folder input or CLI.
Choose Replay recordings in setup to list this installation's completed sessions.
Select a run, inspect its files/evidence, then Replay selected. Browse opens another
recording location. In loaded replay, Open run opens the folder controls.

God's-eye view is enabled by default. Space plays/pauses, Left/Right seeks 1s
(Shift: 10 s), N/M jumps conditions, timeline scrubs forward/back and speed is 0.1–4x.
Right-drag or I/J/K/L turns the camera; middle-drag pans; wheel zooms. W/A/S/D moves
horizontally, Q/E down/up, Shift moves faster. Fit frames all tracks; Perspective/
Top-down changes projection. Back to setup leaves replay. These camera controls
are inactive while entering a path or media form.

Rig colors, markers, heading arrows, recent five-second tails, front-camera cones
and offscreen VR labels help inspect orientation and movement. The faint path
belongs to the current recorded condition, without joining different resets.
Cameras shows the animal front view and available tracker video together; +/-
resizes both within the space above the transport. Animal views preserve saved
projection/aspect where available; they are analysis views, not physical LED
scanout measurements.

Review Save tracker video before initializing the native tracker. Supported
bundled launches enable it by default unless explicitly disabled. End the VR run,
wait for Finishing recording to clear, and finish the independent tracker normally
when its video is complete. Media tools -> Collect media copies completed footage
with integrity metadata; pending media stays explicit. Refresh reloads available
media; Import footage imports a finished external recording. Set offset adds
explicit approximate alignment without rewriting raw footage.

Acknowledged per-experiment recording Start/Stop, recorder-state reconciliation
and manual override are not implemented. A tracker recording may span preflight
and multiple VR runs; stopping the experiment does not stop its recorder.

Trajectory plots opens linked recorded analysis only with the reviewed Mac arm64
Daari Deepa 1486b81e bundle. Older pinned Intel Mac/Windows/Linux dashboards lack
that replay API/assets and show a capability message. Unity's internal pose/video
replay is independent and included in all platform builds.

Replay uses saved evidence and verifies snapshot hashes. It restores supported
built scene geometry, archived skies and recorded populations, freezing live
acquisition. Its fidelity panel identifies missing evidence. Old unrecorded
headings, animations or exact pixels cannot be reconstructed as measurements.
No present-day config is substituted for a missing historical file.

7. PRESERVE DATA AND CHECK THE APPARATUS

Retain the entire updated run directory: configuration versions/hashes, metadata,
rig/population CSV/gzip logs, runtime_trace.log, sky PNGs/manifests and audit files.
Quit cleanly and allow writers to drain. A ZIP made before later media collection
remains its older snapshot; transfer the updated folder to include collected video.
TerrainChoice/rugosity and walking use cm; Selwyn terrain/migration uses metres.
Kinefly raw yaw input uses radians. Interpret units with saved scene/configs.

Repeated-transition cleanup fixes identified ownership leaks/races. The existing
reloadScene:false in-scene sequence remains available; no original crash dump proves
all long-run Unity crashes eliminated. Check physical tracking, LED scanout, display
layout and a representative repeated-reset workload on the acquisition workstation.
See docs/scene-lifecycle.md, docs/data-formats.md, docs/replay.md and docs/releases.md.

8. CURRENT ACCEPTANCE LIMITS

Evenly paced 60 FPS remains unresolved despite high uncapped rendering throughput.
The FPS display reports real delays and peaks; engine averages do not establish
physical LED presentation or camera exposure timing. See docs/frame-pacing-20261027.md.

Latest native Mac keyboard/rendering checks and separate actual Unity GUI-event
checks passed within their recorded scope. Standalone mouse/drag acceptance for
the latest UI remains incomplete because native automation returned
noWindowsAvailable; earlier 0.3.1 pointer checks do not cover every changed control.
Windows/Linux archives are cross-built and have not received native execution
walkthroughs. Older pinned strict flight-camera paths remain blocked on those
platforms and Intel Mac. Physical calibration and representative long-run
acquisition still require the actual apparatus. See docs/releases.md.
