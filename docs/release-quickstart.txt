1. FIVE MINUTES: DEMO -> RECORD -> REPLAY

After downloading, extract the ENTIRE operating-system ZIP into a writable folder.
Keep the player, its data/libraries and this file together. Open the .exe on
Windows, .app on macOS or .x86_64 on Linux. Unity Editor and Python are not needed
for the player. See section 8 for platform requirements and capability limits.

On a fresh desktop profile:
  1. Leave Night sky and Flying demonstration selected; choose Start demo.
     No animal, camera or LED hardware is required. Flying input is simulated.
  2. Focus the player. Use arrows to move and A/D to turn. Ctrl+Space toggles
     forward autopilot. R resets the rig. Run for about 30 seconds.
  3. Choose Back to setup or press Escape ONCE. Wait for Finishing recorders /
     Saving recording to finish. Recording needs attention indicates an error;
     preserve the run folder and inspect its evidence before retrying.
  4. Choose Replay in the sidebar. On Replay recordings, select the newest
     completed run, then Replay selected. Refresh rescans the list.
  5. Space pauses/resumes; Left/Right seeks one second (Shift: ten seconds).
     The default God's-eye view shows the recorded trajectory.

Success: a scene runs, a completed recording appears, and its replay timeline
advances. Pose/configuration recording does not require tracker video. Keep the
whole run folder AND this creating player build for future replay.

Forest and Walking are under Demo options & tracker windows. Walking uses a
finite prerecorded sample; More -> Rig manager... -> Start all in its tracker
window plays the sample again. Demo input is labelled simulated or prerecorded.
Trackers are independent applications; closing Unity does not close them.

Existing profiles retain their saved startup flags. If a sequence auto-starts,
press Escape once or relaunch with -configure to enter setup. Escape from setup
quits the player. For example:
  open "/path/to/MATREX VR.app" --args -configure
  "./MATREX VR.x86_64" -configure

Full five-minute guide and troubleshooting:
  https://github.com/pvnkmrksk/matrexVR/blob/v0.4.1/docs/five-minute-start.md

2. CONFIGURE A REAL APPARATUS

Choose Configure for walking/flying mode, desktop/LED presentation, VR count,
displays, panel dimensions/order, tracker host/port, species and sphere diameter.
Use this configuration saves the apparatus. VR1 through VR16 identify routing;
Animal ID labels the real animal. The public starter is not hardware calibration.
Review every copied rig's endpoint and display rectangles on the actual apparatus.

Use Open tracker to inspect camera selection, source, calibration and input before
starting. Preflight creates no experiment pose recording. Automatic recorder mode
does not begin its native take until experiment Start. Manual mode leaves recorder
operation to the tracker/operator; it can therefore include preflight footage.
Rekkefly is flight input; HejjéTrac walking uses cumulative displacement. Legacy
Kinefly/FicTrac names remain recognized. Do not interchange their input contracts.

Daily work: set animal/experimenter labels and notes under Animal & recording
details, review the sequence, edit a block's Settings, save the setup and choose
Start experiment. Each experiment creates a separate run folder. Auto start
affects the next launch. Plots opens the optional separate Daari Deepa viewer.

The supplied Examples include world starters, four terrain-choice treatments,
swarm/social sequences and custom-model sequences. Settings and Edit JSON share
one document. Actual edits preserve unknown fields and untouched numeric values;
showing inherited defaults does not insert them. Apply/discard pending JSON text
before navigation. Re-read external conflicts; do not overwrite another editor's
changes. Self-contained GLB files can be loaded without rebuilding Unity; a new
Unity scene or controller requires a source build.

3. WRITABLE FILES AND RECORDINGS

Editable configuration: <Unity persistentDataPath>/Config/
Recordings:             <player directory>/MATREX VR RunData/

On macOS, RunData is beside the .app, outside its signed bundle. Protected install
locations use <persistentDataPath>/Installations/<installation-id>/RunData/.
Replay recordings displays the exact root. Browse opens a recording elsewhere.
Updates seed missing config files; existing user JSON is never replaced. Back up
configs before version changes. Older recordings are not moved automatically.

Use absolute overrides for an isolated test profile, for example:
  "./MATREX VR.x86_64" -configure --config-dir "/path/to/config" --data-dir "/path/to/runs"
  open "/path/to/MATREX VR.app" --args -configure --config-dir "/path/to/config" --data-dir "/path/to/runs"

Unity normally places persistentDataPath under:
  Windows: %USERPROFILE%\AppData\LocalLow\<Company>\<Product>
  macOS:   ~/Library/Application Support/<Company>/<Product>
  Linux:   $XDG_CONFIG_HOME/unity3d/<Company>/<Product>
           (usually ~/.config/unity3d/<Company>/<Product>)
Company/Product are the build's Unity Player Settings. Editor defaults remain
Assets/StreamingAssets and Assets/RunData. The local preview launcher instead
uses its explicit Preview/Config and Preview/RunData folders.

4. TRACKER VIDEO: REQUESTED IS NOT ACKNOWLEDGED

Under Animal & recording details, review Save tracker video and Recorder control:
  Automatic / experiment: request a new take from a verified owned compatible
    tracker, then stop that exact take with the experiment and await closure.
  Manual / external: never send automatic recorder Start/Stop commands.
  Video off: pose/configuration recording continues without requesting video.

Recorder preparation is best effort. Missing/unsupported inputs or video produce
per-rig warnings while the VR can start. A successful Start action or a visible
tracker window does not prove camera recording. Automatic acknowledgement needs
the exact take and an accepted/submitted video frame. Experiment Stop waits for
owned native closure and drained VR writers before completing archival.

A manual pause/stop/replaced take, lost endpoint or unresolved closure remains
explicit. The run can retain closed partial artifacts with an error and no
complete ZIP. Inspect native_recording_start.json, native_recording_control.jsonl
and the finalization evidence. Do not infer completion from stable file sizes.
Trackers remain open independently. Reinitialize an old running tracker after an
upgrade; replacing the app does not replace an already-running native process.

This release's reviewed Mac arm64 Rekkefly correction supports automatic owned
recording. Its bundled HejjéTrac and other-platform companions retain their pinned
capabilities: automatic recording can be unavailable; Manual/external operation
and pose recording remain separate. The release manifest and companion catalog
identify the actual payloads. Physical camera acceptance remains a separate test.

5. REPLAY AND PRESERVE EVIDENCE

Use the creating player build. New-contract recordings require matching build
identity and complete, hash-verified saved evidence. A foreign build or missing
required journal/model/config is an error; today's installed JSON is not silently
substituted. Preserve the player archive with its run folders.

Replay reads the complete run folder: config_manifest.json, Configs, replay
contract/journals, rig/population logs, Skyboxes and any media. Extract session
ZIPs before opening. Browse, the folder field or --replay-session can open a run:
  "./MATREX VR.x86_64" --replay-session "/path/to/session-folder"
  open "/path/to/MATREX VR.app" --args --replay-session "/path/to/session-folder"

Space plays/pauses; Left/Right seeks; N/M jumps steps. Right-drag or I/J/K/L turns
the overview, middle-drag pans and the wheel zooms. Fit frames the trajectory.
Choose God's-eye / Animal views; Cameras shows the saved front view and available
tracker video. Replay does not restart acquisition or modify source recordings.
Its fidelity/error messages identify missing or unsupported evidence.

Media tools -> Collect media copies completed app-launched footage; Refresh reads
media already present. Import footage accepts an explicitly finished external
recording. Set offset adds approximate alignment; it cannot recover missing frame
associations. These explicit media actions update the run folder; an older ZIP
remains its original snapshot. Transfer the updated whole folder when sharing.

Recorded input/video association is software timing, not camera-exposure or LED
synchronization. TerrainChoice/rugosity and walking use cm; Selwyn/migration use
metres; raw Kinefly yaw input uses radians. Interpret saved scene/config units.

6. OPTIONAL LOCAL AGENT / MCP CONTROL

Control is off on normal launch. Opt in with --control-dir ABSOLUTE_PRIVATE_DIR;
use a separate private directory for each player, outside its recordings. The
packaged matrex_control_mcp.py adapter and adjacent lock are in MCP/ beside the
Windows/Linux executable, or MATREX VR.app/Contents/Resources/MCP/ on macOS. They
connect through stdio with Python 3.11+ and the pinned SDK; uv run --locked --script
prepares it. Python is needed only for this optional adapter. The adapter may also be used from the
matching source checkout's tools/ directory. Prepare dependencies before offline
experiments. Full client configuration and tool reference:
  https://github.com/pvnkmrksk/matrexVR/blob/v0.4.1/docs/ai-control.md

Discover -> read workspace/schema -> edit JSON with its current revision -> save
and validate -> start -> poll status -> stop -> await finalization -> replay.
Accepted Start means preparation began, not that a scene or recorder is ready.
Read is_error results; after timeout inspect actual status before another mutation.
Re-read stale revisions/conflicts. Quit and relaunch without --control-dir to
remove the endpoint. Agent/contributor context:
  https://github.com/pvnkmrksk/matrexVR/blob/v0.4.1/AGENTS.md

7. EVERYDAY CONTROLS

R                 Reset rigs to the experiment's initial pose.
P / O             Toggle tracked position / orientation.
Arrows; A / D     Manual translation / yaw, when enabled.
Ctrl+Space        Toggle forward autopilot; steering/reverse remain available.
Tab               Hide/restore operator graphics; normal field navigation in setup.
Escape (release)  Return to setup; from setup quit the player.
Kinefly +/-       Yaw gain; Ctrl+Y toggles yaw-rate mode; held [/] changes DC offset.
1-9 / 0           Select matching rig ID / cycle all configured rigs (or Next animal).

Hotkeys are suppressed while entering metadata. Optomotor owns its stimulus
motion. Advanced/gamepad controls and telemetry are documented in the manual.
Default outbound ZMQ telemetry: tcp://127.0.0.1:9880, 20 Hz, matrex.telemetry.v2.
This is separate from tracker input; a static website cannot consume raw ZMQ.

8. PLATFORM REQUIREMENTS AND VALIDATION LIMITS

macOS packages are ad hoc signed, not notarized. Use Finder Open and the relevant
Privacy & Security option if prompted. Linux needs a graphical desktop and a
compatible graphics driver; restore executable permission if extraction loses it.
Bundled Linux HejjéTrac requires glibc 2.39 or newer; use a verified compatible
external tracker on older distributions.

Intel Mac/Windows/Linux strict live-flight camera paths lack the reviewed arm64
correction and can be refused rather than silently substituting sample data.
Their automatic recorder capabilities are also limited. The linked recorded
Daari Deepa viewer is supported by the reviewed Mac arm64 dashboard; other
payloads can report it unavailable. Internal Unity replay is independent.

Software acceptance uses generated/sample input and isolated profiles. Windows
and Linux are cross-built without native walkthroughs. Native OS pointer testing
and physical camera, calibration, display mapping/exposure/LED timing remain
separate. Evenly paced 60 FPS in dense many-camera scenes is not established.
Preserve evidence and run a representative workload on the acquisition computer.
For a problem report include OS, exact build, action/error and runtime_trace.log.
