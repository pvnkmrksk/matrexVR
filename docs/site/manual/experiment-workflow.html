Experiment Workflow

This project runs experiments by chaining Unity scenes and, within some scenes, chaining in‑scene sequence steps. Use this doc as a quick reference when adding or running experiments.

Scene sequencing (sequenceConfig.json)

  • Location: RuntimePaths.ConfigRoot/sequenceConfig.json (Editor: Assets/StreamingAssets; current standalone: writable profile Config).
  • Fields:
    • randomise: shuffle the order of the listed scenes when true.
    • loop: restart from the first scene when the list ends.
    • sequences: array of scene entries. Each entry has sceneName, duration (seconds to run that scene before advancing), optional parameters (passed to the scene controller), and reloadScene (set false to stay in the same scene and let it advance internally).
  • On startup MainController reads this file, copies it into the logging folder, and then walks through the list according to timers and looping rules.

In‑scene sequencing (e.g., Choice_desync)

  • Some scenes implement IInSceneSequencer (e.g., Choice_desync via DynamicSequenceController). When sequenceConfig.json sets reloadScene: false for a step, MainController calls AdvanceStep(parameters) instead of reloading the scene.
  • For Choice_desync, parameters.design points to a sequence design JSON in Assets/StreamingAssets/ (generated by the editor scripts). DynamicSequenceController loads that design and advances through its internal steps based on time or triggers defined per step.

Generating sequence designs

  • Editor menu items under Tools/… generate design JSON files into Assets/StreamingAssets/. Examples:
    • Gray shade angle sweep with mid-trial color swap: Tools/Generate Gray Shade Choice AngleSweep Swap SequenceDesign.json (Assets/Scripts/BuildGrayShadeAngleSweepSwapDesign.cs).
    • Other generators follow the same pattern (e.g., BuildGrayShadeChoiceDesign, BuildStaticDecisionDesign).
  • After generating a design, reference its filename in sequenceConfig.json (e.g., set "design": "sequenceDesign_grayShades_angleSweep_swap.json" for a Choice_desync entry).

Adding a new experiment

  1. Create or modify a generator script under Assets/Scripts to emit the desired design JSON into Assets/StreamingAssets/.
  2. Add/update a sequences entry in sequenceConfig.json with the target sceneName, duration, and any parameters the scene expects (e.g., design).
  3. Ensure the scene controller implements IInSceneSequencer if you plan to stay in-scene (reloadScene: false), or leave reloadScene at true to force a reload between steps.
  4. Play the scene; MainController will load the config, copy it to the log folder, and step through scenes/steps according to your settings.

Continuous heading assessment

For Swarm or ordinary Choice, enable headingReference in the individual experiment config. The rig continues tracking through assessment and stimulus onset, with no onset reset. Heading observation shares the configured scene/phase timer and is capped to the remaining duration; it does not add time to a condition. See heading-relative presentation for a reusable component API and the required stimulus adapter when adding new controllers.
